Concepts

Ideas I keep coming back to. Each one: what it is, where it comes from, and where it fits.

List processing

  • Use one structure, the list, for both data and code. A program is a list, so a program can read, build and change other programs.
  • It's where Lisp gets its name: LISt Processing.
  • Where it fits: an agent's plan written as structured tool calls is data that a program runs. The agent writes code as data, the way Lisp does.
  • John McCarthy, "Recursive Functions of Symbolic Expressions and Their Computation by Machine" (1960) · Paul Graham, "The Roots of Lisp" (2001)

Top-down design

  • Start from the whole, split it into parts, then split those, until each part is small enough to build.
  • Good when the goal is clear and stable.
  • The risk: you design the parts before you know which ones are hard.
  • Niklaus Wirth, "Program Development by Stepwise Refinement" (1971)

Bottom-up design

  • Build small, general pieces first, then make bigger things out of them.
  • Good when you learn what the problem is by building it.
  • The risk: nice pieces that never add up to the thing.
  • Use it together with top-down: split the program down toward the language, and build the language up toward the program. The program gets smaller and the pieces can be used again.
  • Paul Graham, "Programming Bottom-Up" (1993)
