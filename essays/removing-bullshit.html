Removing Bullshit

November 2026. 600 words.

Looking back at every system I’ve built, the part that took the longest was never adding things. It was taking them out. The format I ended up with has three marks on a line. It took years to get there, and almost all of that time went into removing things that should never have been there.

I call those things bullshit. Not because they’re stupid. Most of them sound sensible. They’re bullshit because they cost something every day and change nothing about what you do.

What it looks like

A priority scale where everything ends up high. Tags you add and never filter by. Effort estimates you never compare to anything. Projects inside projects inside areas. A weekly review that exists in the template and not in your week. A dashboard nobody opens. A setting for a user you imagined. A status field with seven values when you only ever use two.

Each one is cheap on the day you add it. That’s the trap.

Why it piles up

Adding feels like progress. A new field, a new view, a new rule: each one makes the system look more complete, and the cost doesn’t show up until later. When it does, it comes as upkeep. Every field has to be kept current. Every feature has to be kept working. Every rule has to be remembered.

The worse cost is trust. Once a few fields go stale, you stop believing the system, and a system you don’t believe is worse than none, because you still act on it.

For a brain like mine there’s a third cost. Every field is a decision at the moment of capture. Which project? What priority? Which tags? Decisions are exactly what I have least of, and when capturing gets hard, I stop capturing.

The tests

I use two questions, one for each layer that has to last.

For data: does a feature need this? Keep a fact only if something actually reads it. If no view, no decision and no question ever uses a field, it’s bullshit, however reasonable it sounds.

For features: do I actually ask this question? Keep a feature only if it answers something I ask in real life, not something I think I should ask. “What’s started?” I ask every morning. “How much effort is left across all projects?” I’ve never asked.

And one test for anything: what would I do differently if this were gone? If the answer is nothing, it goes.

Where it’s allowed

There’s one place I don’t cut: the surface. Colors, a nicer font, a new layout, a view I built because I was bored. None of it is necessary, and that’s fine, because none of it is permanent. Excess on the surface gets thrown away with the surface. Excess in the data or the features stays and compounds. So I keep the spine strict and let the surface be as indulgent as I like.

Hackathons are good practice for this. With a day and a half, bullshit removes itself. There’s no time for the settings page, so the demo shows the one thing that matters. Most of the projects that impress are the ones that were forced to be simple.

What’s left

When you’re done cutting, what remains looks too simple. Three marks on a line. A few areas. One file. It looks like you didn’t try. That’s the sign it’s finished: every piece left is something you’d miss.

Most of what I’ve called design was this. Not deciding what to build, but deciding what the system doesn’t need to know, and doesn’t need to do.
