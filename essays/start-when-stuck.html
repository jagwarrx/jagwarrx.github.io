When It’s Not Working, Start

November 2026. 418 words.

Usually, when something is not working, I just need to start. So that’s where I look first: the start.

What “not working” looks like

It rarely shows up as “I haven’t started.” It shows up as a reason. The plan is wrong. The system needs fixing. I need to read one more thing first. It’s the wrong time of day. I’m too tired for this one.

Some of those are true. But most of the time, when I look closely, the thing isn’t failing. It isn’t running. A plan that hasn’t been started can’t be working or not working. It hasn’t been tested.

So the first check is plain: did I start? Most of the time, the answer is no.

Why the start

Once it’s moving, it mostly keeps moving. The trouble is the gap before the first move, not the work after it. I wrote about this in One Thing at a Time, and it’s the same here.

The feeling comes after. Waiting to feel like it is waiting for something that usually arrives only once I’m doing the thing. Behavioral activation, a therapy for depression, is built on this: act first, and the mood follows.

Starting is how I find out. Thinking about a stalled thing gives me more thoughts about it. Ten minutes of doing it tells me whether the plan is actually wrong, and where.

How to focus on the start

Make it tiny. Not “write the essay.” Open the file and write one line. The start should be so small there’s nothing to resist.

Name the physical action. What will my hands do first? Open, type, call, pick up. David Allen calls this the next action. If I can’t name it, that’s the real problem, and it’s a small one.

Start before I feel ready. Ready is a feeling, and feelings come after the start.

Count the start, not the finish. Five minutes and then stopping still counts. Counting starts counts the hard part.

Plan the start the night before. When it’s nine, open the draft. Then the morning has no decision in it, just a start.

When it really isn’t working

Sometimes the plan is wrong. The way to know is that I started, a few times, and it still failed. Now it’s a real fault, and a real fault can be written down: what went wrong, and when. Then it’s worth fixing.

The order matters. Start first, fix second. Fixing before starting is redesigning something that was never run.
