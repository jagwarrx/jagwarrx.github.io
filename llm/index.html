The whole machine

One guess at a time

Type “The cat sat on the” and GPT-2 has exactly one job: guess the next token, which is a word or a piece of one. Everything you're about to build exists to make that one guess good.

Cutting text into tokens

The model can only do arithmetic, and “cat” isn't a number. So GPT-2 keeps a fixed list of 50,257 pieces of text, each with an id, and your sentence turns into a list of ids.

A rarer word gets cut into several pieces, something like:

␣Thirukkural

The list comes from byte-pair encoding. Start from single bytes and keep merging the most common pair. Common words end up as one token, rare ones as several.

A row for every token

An id is a name tag. 3797 says nothing about cats, and 3798 isn't nearly a cat. So GPT-2 keeps a table with one row of 768 numbers per token, and the id says which row to copy. Words that behave alike can end up with rows that look alike.

That's 50,257 rows of 768 numbers, or 38.6 million. Almost a third of GPT-2 small sits in this one table.

Where each token sits

The next part reads all five tokens at once, with no sense of order. “Dog bites man” and “man bites dog” would look almost the same to it. So each position gets a row of its own, added onto the token's row.

My LSTM never needed this. It read one word at a time, so order came for free.

Keeping the numbers tame

Rows pass through dozens of steps, and their numbers drift. Some grow huge, some shrink to nothing, and training starts to wobble. So before each big step, every row is shifted and scaled to an average of 0 and a spread of 1. Two learned knobs per number then nudge it to wherever is useful. This is LayerNorm.

Asking, and being found

To guess what follows “the”, the last token needs things from earlier. Who sat? On what? So each row goes through three tables of weights and comes out as a query (what it's looking for), a key (what it can be found by) and a value (what it hands over).

Those names are our story. Nothing tells the model what to put where; training decides.

Who listens to whom

Now every query meets every key, one dot product per pair. The score is high when the two line up. GPT-2 divides each score by 8 (the square root of its 64-number heads) to keep things calm. The toy divides by 2.

In training the next word is the answer, so no token may look ahead. Blocking the future is called the causal mask.

Taking a share of each

Scores can be any size, so softmax turns each row of them into shares that add up to 100%. Each token then builds a new row by blending the value rows by those shares. This is the only place in the model where tokens pass anything to each other.

My LSTM lost the thread because it squeezed everything it had read into one memory row. Here, ␣the just looks straight back at every word before it.

Several heads at once

One blend can't track everything. The word just before matters, and so does the subject three words back. So attention runs as several heads side by side, each on its own slice of the row. The toy has 3 heads of 4 numbers. GPT-2 has 12 heads of 64.

The stream

If attention overwrote each row, anything it missed would be gone for good, and twelve blocks of that would be miserable to train. So its output is added onto the row it started from. There's nothing new to learn here, and in training the error signal slides back along this same line.

Thinking alone

Attention gathered things into each row but only blended them. The MLP works on each token by itself. It widens the row to four times its size, bends it, narrows it back and adds the result to the stream. In GPT-2 that's 768 numbers out to 3,072 and back.

Without the bend, the two tables would collapse into one. About two-thirds of each block's numbers live in this part.

That's one block

Everything so far is one transformer block. Tokens talk to each other in attention, then each one thinks alone in the MLP, and both add to the stream. Rows go in and rows of the same size come out, which is what lets you stack them.

Attention itself dates from 2014. What was new in 2017 was a model built from attention alone, with no reading word by word.

Twelve of them

One block gives each token one look around. Working out who “it” is, or who did what to whom, takes more rounds than that. So GPT-2 stacks 12 blocks of the same design, each with its own numbers, and the stream runs through all of them. GPT-3 stacks 96.

Back to words

After 12 blocks, the last row holds the model's best idea of what comes next, written as 768 numbers. To get a word out, GPT-2 normalises it once more and scores it against every row of the token table from the start. That's one score for each of the 50,257 tokens.

In training, every row is scored against its own next token, all at once. When writing, only the last row matters.

Scores into odds

A score of 5.2 doesn't tell you how sure the model is. The same softmax you saw in attention turns all 50,257 scores into odds that add up to 100%.

The toy is untrained, so its odds would be noise. These bars are made up to look like a trained GPT-2.

Rolling the dice

Always taking the top token reads flat, and it tends to loop. My LSTM kept reusing words for much the same reason. So GPT-2 rolls dice weighted by the odds. Temperature divides the scores before softmax, and top-p keeps only the fewest top tokens whose odds reach p.

Again, and again

One pass gives one token, and a reply needs hundreds. So the picked token is added to the input and the whole stack runs again, until it hits a stop token or a length limit. A cache keeps the old keys and values, so each lap only works out the new token's rows.

The cat sat on the

My LSTM also wrote one word at a time. The difference is in training: a transformer checks every position of a sentence at once, while an LSTM has to step through. That's what made huge training runs practical.

Where the numbers come from

Every number so far was random, which is why the toy picked . Training is brute force. Show it real text, measure how surprised it was by the actual next token, and nudge all 124 million numbers to be a little less surprised. Then repeat, over billions of tokens.

step 0 · loss 10.82 · the real next token gets 1 in 50,000

My LSTM saw about 1,000 couplets. GPT-2 saw roughly 9 billion tokens of web pages.

More of everything

GPT-2 writes passable paragraphs. GPT-3 writes essays and working code. It's the same block, 8 times deeper and 16 times wider, trained on about 30 times more text.

From autocomplete to assistant

A base model continues documents. Ask it a question and it may well reply with more questions. So it gets trained a little more, first on example chats and then on which of two answers people preferred. That second part is called RLHF.

All it can see

It has no memory between messages. All it knows about your chat is the text in its window, which holds your prompt and the chat so far, including its own reply as it writes.

Slide to compare window sizes. Grey text is outside the window; to the model it doesn't exist.

Double the text and attention does about four times the work. Facts buried in the middle of a very long window often get missed.

Eight moves and a loop

Look up a row, add two rows, normalise, take a dot product, softmax, mix by shares, bend, and pick. GPT-2 is those eight, repeated, inside a loop.

Today's models add longer windows, mixtures of experts, tools and reasoning steps. Under all of it is the same loop: guess the next token, append it, go again.
